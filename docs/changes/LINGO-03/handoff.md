## Executor decisions
- D-01 (P-07a, ADR-0002): `@types/node` (dev, types only) is added to the ADR-0002 allow-list; core-ts tests read `packages/contracts`
  through `node:fs`, and the engine tools will need the same. It brings no runtime code. The owner may object; the alternative is
  untyped test helpers.
- D-02 (P-07a, ADR-0004): `workspaces` lists `packages/core-ts` (and later `services/engine`, `apps/web`) instead of `packages/*`,
  because `packages/contracts` is data without a `package.json` and must not become a workspace.
- D-03 (P-07b): the TS event reader follows Swift `JSONDecoder` + `Event(line:)` with these documented differences: stricter where Swift
  never writes such input — `ts` must match the contract pattern (Swift also accepts other ISO 8601 forms) and `v`, `seq`, `lamport`
  must be safe whole numbers (Swift truncates, and traps on huge values); still different — a duplicate key keeps the last value
  (`JSON.parse`) where Swift keeps the first, and keys that differ only by Unicode normalisation stay separate. Lines with lone
  surrogates or numbers beyond the Double range are rejected by both.
- D-04 (P-07c): the TS reducer compares ids and devices by UTF-16 code units; both are ASCII by contract (ULID and the device
  pattern), where this equals Swift's order. Phrase keys are lower-cased per code point, split on Swift's whitespace set and
  NFC-normalised, so canonically equivalent texts give one key as in Swift. Payload integers accept whole numbers in the Int64 range
  (Swift decodes them through Double); event `seq`/`lamport` stay safe integers (D-03).
- D-05 (P-07d): interruption offsets (R-12) are read as Characters of the spoken text (`spokenText.prefix(at)`, the fixture
  checks this), but the Mac `TurnController` writes them in UTF-16 units plus one per part, so emoji and double spaces shift them by a
  few positions.
