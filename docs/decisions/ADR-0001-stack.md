# ADR-0001: Lingo stack and architecture (LINGO-01)

Status: **accepted** (2026-10-25) · Date: 2026-10-25 · v2: LINGO-01 is Mac only, the iOS parts move to LINGO-02 (Q27) · Owner: itmax04 ·
Links: [intent](../changes/LINGO-01/intent.md), [spec](../changes/LINGO-01/spec.md), [plan](../changes/LINGO-01/plan.md)
The "Final decisions" section at the end is filled in by the executor from the measurements (P-04, P-05). The iOS items (item 2 — LingoProbe, item 5, the iOS candidates of items 6 and 8) are implemented in LINGO-02.

## Context
- Two separate apps: macOS (MacBook Air M1, 8 GB, macOS 15.7.2) and iOS.
- The iPhone comes in LINGO-02 (Q27). Candidates: iPhone Air (A19 Pro, 12 GB, Apple Intelligence available) and/or iPhone 11 (A13, 4 GB, no Apple Intelligence; A-9).
  Therefore the main local path is our own model through llama.cpp, which works on both. Apple's built-in model is only an additional candidate.
- Budget $0: a free Apple ID, installation through SideStore (7-day signature, up to 3 apps, up to 10 App IDs per week),
  free tiers of cloud models. EU region.
- There is working Interview Copilot code (Swift 6, SwiftPM): provider chain, SSE, Keychain, whisper.cpp.
- Xcode 26.3 is installed. About 14 GB free.

## Shell options
| Option | Pros | Cons |
|---|---|---|
| **Swift (SwiftUI) on both platforms + a shared `LingoCore` package** | Native audio (AVAudioEngine, voice processing), Speech, AVSpeechSynthesizer, Keychain, file picking; reuse of IC code; minimal memory | Two UI layers |
| React Native / Flutter | One UI | Audio, echo cancellation and llama.cpp are native anyway; more memory on a 4 GB iPhone |
| Web app (PWA) | No signing | No background work, no local model of the needed class, no reliable access to the iCloud folder |

## Decision
1. **Language and UI:** Swift 6, SwiftUI. Mac — a SwiftUI window (AppKit only where needed). iOS — SwiftUI.
2. **Structure:**
   - `Package.swift` (SwiftPM), targets:
     - `LingoCore` — logic, no UI, testable;
     - `LingoMac` — the macOS app, as in IC: `scripts/build-app.sh` builds the `.app`;
     - `lingo-eval` — a CLI for evals on the Mac;
     - `LingoCoreTests`.
   - (LINGO-02) the iOS app `LingoProbe` (utility): the project is generated by **XcodeGen** from `ios/project.yml`, the `.xcodeproj` is not kept in Git.
     It depends on `LingoCore` as a local package. `scripts/build-ipa.sh` builds the `.ipa` for SideStore (`xcodebuild archive`, unsigned
     or ad-hoc signed, `Payload/` packaging); SideStore re-signs it.
3. **Bundle ID:** iOS — `com.itmax04.lingo` (the same for the future iPhone MVP, A-6; SideStore appends its own team suffix),
   Mac — `com.itmax04.lingo.mac`.
   **Mac signing:** a local self-signed certificate, by default the existing "InterviewCopilot" one (A-5). Then the TCC permissions are not reset on rebuild.
4. **Models — cloud:** ported from IC: `ProviderChain`, `ProviderHealth`, `SSEClient`, `KeyVerifier`, `KeychainStore`, OpenAI-compatible providers.
   Changes per R-29: "provider + model + key" steps, an unlimited number of keys, disabling a single key, a pause by `retry-after`.
   Providers per R-30: Groq (main), Mistral (free tier), OpenRouter `:free`, a custom address.
   Removed: Gemini (EU), DeepSeek and Anthropic (paid), Cerebras (no free tier as of 2026-10, per the data).
   The default models are chosen in P-03 from `GET /models` and the `dialog` eval. The Groq candidates are the strongest free chat models
   in the list on the date of P-03 (per third-party data: the GPT-OSS and Qwen families). Groq limits are counted per model, so 2–3 Groq models
   go into the chain before the fallback providers.
5. **Models — local (iOS):** llama.cpp (an XCFramework from the releases, `binaryTarget`, the same approach as in IC), GGUF format, Q4_K_M quantization.
   Candidates for measurement (current versions and SHA256 are fixed in P-05 from Hugging Face):
   | Candidate | ≈Q4 size | Why it is listed |
   |---|---|---|
   | Qwen3 1.7B Instruct | 1.1 GB | Strong multilingual model at a small size |
   | Gemma 3 1B IT | 0.8 GB | The lightest, memory headroom |
   | Llama 3.2 3B Instruct | 2.0 GB | Better quality, at the memory limit |
   | Gemma 3n E2B IT | ≈2 GB | Multilingual, check support in llama.cpp |

   If newer models of the same class (up to ≈2 GB) exist on the date of P-05, the executor adds them and records it here.
   On the iPhone Air with 12 GB, larger candidates are added to the measurements: Qwen3 4B, Gemma 3 4B (≈2.5 GB Q4), up to 8B if the app memory limit allows.
   An additional candidate is Apple's built-in model (`FoundationModels`, ≈3B). It is free and needs no download. Limitations:
   - per the data found, it does not support Russian;
   - it requires a supported iPhone system language;
   - it is not available on the iPhone 11.

   A future risk (iPhone 11): the A13 GPU (Apple6 family) may not support some of the llama.cpp Metal kernels. Then only the CPU is used there. Checked in a separate intent.
   The wrapper's KV cache is reused (R-31). The actual backend is recorded in P-05.
   Risk: iOS forbids the GPU in the background, so with a locked screen the local model runs on the CPU only (F-10).
6. **Recognition:** a `SpeechRecognizer` abstraction with several engines. The choice follows the F-06 and AC-16 measurements.
   - iOS candidates:
     - Apple `SpeechAnalyzer`/`SpeechTranscriber` (iOS 26+; check `isAvailable` and the locales en-US/en-GB, de-DE, ru-RU);
     - `SFSpeechRecognizer` with `requiresOnDeviceRecognition`;
     - whisper.cpp `base`/`small` multilingual (language auto-detection, mixed speech; memory).
   - Mac candidates: whisper.cpp `large-v3-turbo` q5_0 (as in IC), fallback `small` q5_1; `SFSpeechRecognizer` (`SpeechAnalyzer` is not available on macOS 15).
   - Utterance language: whisper auto-detection, or for the Apple engines — parallel recognition of {study language, ru} with a choice by confidence,
     if that fits the memory and latency. Otherwise — R-09 (the button).
7. **Speech synthesis:** `AVSpeechSynthesizer`, on-device en, de, ru voices (premium, then enhanced, then default). The reply is split into segments per R-24.
8. **Audio and barge-in:** `AVAudioEngine` with `setVoiceProcessingEnabled(true)` on the input (echo cancellation).
   iOS: `AVAudioSession` `.playAndRecord`, mode `.voiceChat`, `allowBluetooth`, `UIBackgroundModes = audio` (Info.plist, no paid entitlement).
   Note: an AirPods microphone switches the audio to HFP with worse quality. This affects F-06 and F-09 and is recorded in the measurements.
   VAD — an energy-based one with an adaptive threshold. If it does not pass the `turn` eval, Silero VAD (ONNX) is added and recorded here.
9. **Storage and sync:** JSON Lines journals (R-34…R-39), our own code, no database. The index is in memory.
   If the number of events exceeds 100 thousand, the system SQLite (`libsqlite3`, no dependency) is added and recorded here.
   Folder access: a security-scoped bookmark; `NSFileCoordinator`; `FileManager.startDownloadingUbiquitousItem`.
   No iCloud entitlements and no CloudKit — they require a paid account.
10. **iOS metrics:** `task_vm_info.phys_footprint`, `os_proc_available_memory()`, `ProcessInfo.thermalState`, MetricKit (`MXAppExitMetric`).
11. **Dependencies (allow-list):**
    - Yams — if YAML is needed for the evals;
    - llama.cpp XCFramework;
    - whisper.cpp XCFramework;
    - XcodeGen (Homebrew, build only);
    - Silero VAD (ONNX) — only if the condition of item 8 is met.

    Everything else is an entry in this ADR and a "needs owner confirmation" note in the handoff.

## Consequences
- The Mac and the future iPhone MVP use one core. The iPhone UI (LINGO-02) is added without reworking the logic and the history format.
- Without a paid account there is no CloudKit and no push. Sync is by polling the folder, not instant (R-38).
- Models are downloaded on first use. The IPA stays small, and SideStore installs it faster.
- Mac disk: the candidate models (≈6 GB) are deleted after the choice. Only the chosen Mac whisper model is kept.

## Final decisions (filled in by the executor)
- iOS recognition: _(LINGO-02)_
- Mac recognition (P-04, H-2): **whisper.cpp large-v3-turbo q5_0**, Metal, language — a double pass
  over the candidates {study language, ru} with a choice by the mean token probability, an encoder context trimmed to 512 frames, a bilingual
  `initial_prompt` seed, a language label from the alphabet of the text. The synthetic `evals/audio` set (75 `say` recordings): en/de/ru — 20/20 understood, language 100%;
  mixed 13/15 auto and 13/15 with the button; ≈ 1.5 s per phrase, process memory ≈ 760 MB. small q5_1: 0.5 s, but mixed 5/15.
  **H-2 (the owner's live phrases, 18 steps): whisper chosen.** whisper — en 4/4, de 4/4, ru 4/4, mixed 2/3 auto and 3/3 with the button, language 12/12,
  ≈ 1.4 s; Apple `SFSpeechRecognizer` (on device) — en 2/4, de and ru without a result, language confused. The decision is final for LINGO-01;
  small q5_1 was removed from the Lingo models folder. The context hint for recognition is R-51 (Q28).
- iOS local model and backend (Metal or CPU): _(LINGO-02)_
- Default chain (Groq models and fallbacks): _(P-03/P-05)_
- VAD (P-04): energy-based with an adaptive threshold (a port of `EnergyVAD` from IC), hangover 200 ms; end of utterance and merging — `TurnSegmenter`. `turn` eval: 0% cut-offs and 0% false merges on 29 utterances (timeline and synthesis through the VAD). Silero VAD was not needed (the condition of item 8 was not met).
