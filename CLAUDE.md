# Инструкции проекта Lingo

@DESIGN.md

## Проект
Lingo — личное приложение для голосовой разговорной практики английского и немецкого. Объяснения на русском даются по явной просьбе.
Два приложения на Swift 6 / SwiftUI с общим ядром `LingoCore`:
- macOS: SwiftPM, `.app` собирает `scripts/build-app.sh`;
- iOS: в LINGO-02. Ядро уже сейчас собирается для iOS (`scripts/check-core-ios.sh`).

Карта, команды и ограничения — `README.md`. Стек — `docs/decisions/ADR-0001-stack.md`.
Текущая задача — `docs/changes/LINGO-01/` (intent → spec → plan → handoff).

## Проверки
- Быстрая: `swift build && swift test`
- Полная: `swift test && scripts/run-evals.sh all && scripts/secret-scan.sh && scripts/build-app.sh && scripts/check-core-ios.sh`
- Команды появляются по шагам plan.md. Если команды ещё нет, так и пиши (NOT RUN) и не выдумывай результат.
- `LingoCore` должен собираться и для iOS: `scripts/check-core-ios.sh`. Платформенный код Mac — только в `LingoMac`.
- iPhone — в LINGO-02 (Q27). В LINGO-01 iOS-приложение, SideStore и F-проверки не делаются. Симулятор и одиночный запуск интерфейса — не свидетельство.

## Правила
- Отвечать владельцу по-русски.
- Ключи API и личные данные не писать в код, логи, тесты, коммиты, журналы синхронизации и сообщения.
  Тестовые данные только синтетические. `private/` (оригинал PDF) никогда не коммитить.
- Работать в ветке `feat/lingo-01`. После каждого шага plan.md — коммит и `git push`.
  Запрещено: force-push, `reset --hard`, удаление веток, переписывание истории, merge в `main` без решения владельца.
- Только бесплатное: никаких платных API, подписок, провайдеров с обязательной картой, платного аккаунта Apple Developer.
- Новые зависимости — только из ADR-0001 п. 11. Любая другая требует записи в ADR и отметки в handoff.
- Модели скачивать только с официальных репозиториев по HTTPS, с проверкой SHA256. Неиспользуемые модели удалять: на диске ≈14 ГБ.
- Не вводить Apple ID, пароли и ключи и не просить их в чате. SideStore, «Режим разработчика», TCC и Keychain trust настраивает владелец по инструкции.
- Вопросы владельцу — только в точках H-0…H-5 из plan.md. Остальные неоднозначности решать самостоятельно
  по spec, DESIGN.md и Apple HIG и записывать в handoff.md («Решения исполнителя»).
- После каждого шага обновлять `docs/changes/LINGO-01/handoff.md`: что сделано, коммит, проверки (PASS/FAIL/NOT RUN), следующий шаг.

## Дизайн
- Источник стиля — `DESIGN.md` (токены сняты с `docs/design/lingo-mac.webp`). Значений, которых там нет, не придумывать.
  Если значения не хватает, дописать его в DESIGN.md с пометкой и показать владельцу при приёмке.
- Из глобальных правил фронтенда владельца применяется DESIGN.md. 21st.dev и Kinetics дают React-код и к нативному SwiftUI не применяются.
  component.gallery можно использовать только для проверки состояний и доступности компонентов. При использовании — указать источник в отчёте.
- Анимации — системные. Учитывать «Уменьшить движение» (`accessibilityReduceMotion`).
- Интерфейс iPhone не проектировать: его дизайн пришлёт владелец (LINGO-02).
